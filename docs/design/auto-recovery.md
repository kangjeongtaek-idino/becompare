# 자동 복구 — 설계 기록

2026-11-26 설계, 2026-11-27 구현(PR #2). 사용자 관점의 설명은 [README](../../README.md)의 "자동 복구" 단락과 F1 도움말에 있고, 이 문서는 왜 이렇게 만들었는지와 저장 형식을 남깁니다.

## 목적

앱이 비정상 종료(크래시, 강제 종료, 정전)되면 저장하지 않은 편집 내용이 사라졌다. 수정 중인 내용을 주기적으로 따로 보관하고, 다음 실행 때 되살릴지 묻는다. 2026-10-14 리뷰의 "복구용 자동 저장" 과제.

- 대상: 텍스트 비교의 두 창, 텍스트 편집기, 텍스트 병합 출력, 헥스 창.
- 대상이 아닌 것: 폴더 작업(복사·동기화)의 재시작 후 되돌리기, 탭 배치 복원, 표·이미지 같은 읽기 전용 화면.
- 하면 안 되는 것: 사용자 폴더에 파일을 만들기, 무인 실행에서 기록하거나 창을 띄우기, 실행 중인 다른 인스턴스의 보관본을 건드리기, 복구가 원본 파일을 덮어쓰기.

## 검토한 방식

1. **설정 폴더에 주기적으로 보관 (채택)** — 강제 종료·정전에도 남고 사용자 폴더를 건드리지 않는다.
2. 원본 옆에 `~` 파일 — 사용자 폴더를 어지럽히고 폴더 비교·동기화 대상에 섞인다.
3. 크래시 순간에 저장(예외 필터) — 강제 종료·정전에는 동작하지 않고, 손상된 상태에서 쓰게 된다.

## 구조

- `gui/recover.c`: 보관본 저장소, 끝난 프로세스 판별, 시작할 때의 목록 창. Windows API 위주라 `concurrency.c`, `help.c`처럼 C 지원 모듈로 두었다.
- 프레임 타이머(id 92)가 모든 탭에 `BC_SNAPSHOT`을 보낸다. 각 화면은 창별로 수정됐으면 `rc_put_text` / `rc_put_bytes`, 아니면 `rc_drop_slot`을 부른다. 폴더 비교는 아래쪽 미리보기 화면에 전달한다.
- 텍스트는 저장했을 때와 같은 바이트로 보관한다. 그래서 저장 함수에서 내용 준비 부분을 떼어(`ed_text`, `tv_side_text`, `mg_out_text`) 저장과 보관이 같은 코드를 쓴다.
- 접기·통합 보기·공백 표시 상태의 텍스트 비교는 창의 글자가 파일 내용이 아니므로 `tv_side_text`가 보관된 실제 텍스트(`TV_TXA` / `TV_TXB`)를 돌려준다. 보관이 보기 상태를 바꾸지 않는다.
- 화면의 `WM_DESTROY`가 `rc_drop`을 부른다. 탭 닫기("저장 안 함" 포함)와 정상 종료가 모두 이 경로라서 보관본이 지워지고, 비정상 종료에서는 이 경로를 타지 않아 남는다.
- 타이머는 틱마다 설정의 간격으로 자신을 다시 건다. 환경설정을 저장하면 틱을 한 번 보내 간격과 사용 여부가 바로 적용된다.

## 저장 형식

```
%LOCALAPPDATA%\BeCompareAsm\recover\
  <PID 16진>_<번호>\                 실행 중인 프로세스의 화면 하나
    0.dat, 1.dat                     창(왼쪽/오른쪽)의 내용
    info.ini                         [Owner] Started=<프로세스 생성 시각>
                                     [0] / [1] Path= Type= Bytes= Time=
  <PID 16진>_c<생성 시각 16진>_<번호>\   나중 실행이 가져간(제안 중인) 폴더
```

- 같은 내용은 다시 쓰지 않는다(내용·경로·옵션의 해시 비교).
- 크기 한도는 로컬 기록의 `[History] MaxFileMB`를 그대로 쓴다(텍스트는 글자 수, 헥스는 바이트 수 기준).
- 보관에 실패하면 알림 없이 건너뛴다. 타이머가 간격마다 창을 띄우면 안 되기 때문이다.

## 끝난 프로세스 판별과 선점

- 프로세스 ID는 재사용되므로 ID와 생성 시각을 함께 본다. 폴더의 PID로 프로세스를 열 수 없거나, 살아 있어도 생성 시각이 기록과 다르면 끝난 것으로 본다. 생성 시각이 아직 기록되지 않은 폴더는 만드는 중으로 보고 건드리지 않는다.
- 시작한 인스턴스는 끝난 프로세스의 폴더 이름을 `<자기 PID>_c<자기 생성 시각>_<번호>`로 바꿔 가져간다. 이름 바꾸기는 한 프로세스만 성공하므로 두 인스턴스가 함께 시작해도 같은 항목을 함께 제안하지 않는다. 생성 시각을 이름에 넣은 것은 이름 바꾸기와 소유 표시가 한 번에 일어나야 하기 때문이다(따로 기록하면 그 사이에 다른 인스턴스가 끝난 프로세스의 것으로 오인한다).
- 가져간 폴더는 그 인스턴스가 끝나면 다시 끝난 프로세스의 것이 되어 다음 실행이 제안한다. `나중에`가 이 방식으로 동작한다.

## 복구

- 원본을 덮어쓰지 않는다. 보관본을 임시 폴더에 복사해 왼쪽에, 현재 파일을 오른쪽에 둔 비교 탭으로 연다(헥스는 헥스 비교). 로컬 기록이 버전을 여는 방식과 같다.
- 파일이 없어졌거나 경로가 없던 문서는 편집기로 열고 경로 칸을 비운다. 임시 폴더의 경로가 저장 대상으로 남으면 종료 때 지워지기 때문이다.
- 복구로 연 뒤에도 보관본은 남는다. 연 화면과 묶어 두었다가 그 화면이 파일을 저장하면(`rc_saved`) 지운다. 처음에는 여는 즉시 지웠는데, 왼쪽이 임시 복사본이라 저장 없이 탭을 닫으면 내용이 사라졌다. 저장 없이 닫으면 다음 실행 때 다시 제안하므로, 필요 없는 항목은 `버리기`로 지운다.

## 알려진 제한

- 마지막 보관 이후의 입력(기본 최대 30초)은 되살릴 수 없다.
- 복구한 화면에서 저장했는지만 본다. 같은 파일을 다른 탭이나 다른 프로그램에서 저장해도 보관본은 남는다.
- 명령줄로 세션을 지정해 실행해도(예: `git difftool`) 보관본이 있으면 복구 창이 먼저 뜬다.
- 복구 창은 다크 모드를 따르지 않는다.
- 경로 칸을 바꾸고 아직 다시 비교하지 않은 텍스트 비교 창은 새 경로와 이전 내용이 함께 기록된다.
